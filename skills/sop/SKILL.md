Turn how someone does a task into a procedure a new colleague can follow alone.

## Mode

- **Direct**: the user pasted a transcript, notes or an old SOP. Produce the draft at once.
- **Guided**: only a title or a vague idea. Ask one numbered round, max 6 questions, each with a suggested answer in brackets so "yes" accepts all (who does it, how often, tools used, what goes wrong, who approves, where the SOP lives). Show a 4-6 line brief (goal, reader, format, length) first. Max 2 rounds.

Write in the user's language. Never ask what the notes already say.

## Do this

1. Read the explanation and list every action in order. Spoken text jumps around; fix the order, but do not add steps the person did not describe.
2. Write the SOP with these parts:
   - **Title and purpose**: one sentence, the result it secures.
   - **Use when / do not use when.**
   - **Prerequisites**: access, tools, files, approvals needed before step 1.
   - **Steps**: numbered, one action each, starting with a verb, naming the exact button, file or system. Put a warning on the step it applies to, not at the top.
   - **Check**: after key steps, how to see it worked ("status shows Sent").
   - **If it fails**: symptom, first fix, who to call.
   - **Owner, version, last review date, next review date.**
3. For an existing SOP, keep its structure, fix gaps and list what you changed in 3-5 lines.
4. Where the notes are silent, insert a visible placeholder such as [WHO APPROVES] instead of guessing.
5. Offer a one-page checklist version only if the task repeats daily.

## Stop and ask when

The task touches money, safety or legal duties and the notes contradict each other.

## Done when

- Every step holds one action and one object.
- A stranger could run it without asking the author.
- Each risky step has a check or a warning.
- Owner and review date are present or marked as placeholders.

## Traps

- Steps like "handle the invoice": split them until each can be observed.
- Words like "as usual" or "the folder": name the thing.
- Writing the ideal process instead of the real one; note the real one, flag the gap.

End with the list of placeholders, then "Check before using": walk the steps once with someone who has not done it; confirm names, links and approvers; confirm the review date.
